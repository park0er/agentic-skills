01
Oracle Always Free 机型选择

Oracle 的 Always Free 额度里有两类可选算力，日区（Japan Central / Osaka 或 Japan East / Tokyo，取决于你注册时选的 Home Region）都覆盖。选错机型不会花钱，但会影响后续能不能扛住多设备/多协议。

VM.Standard.A1.Flex（Ampere ARM）

最多 4 OCPU + 24 GB RAM · 可拆成多台小实例

这是目前 Always Free 里最强的选项，永久免费，不是试用额度。整租一台 4C24G 完全够用，一个人或者三五好友用 REALITY 节点绰绰有余，还能同时跑面板、简单的 Web 服务。

  • ARM 架构，Xray-core / sing-box / 3x-ui 官方脚本均原生支持 ARM64
  • 免费额度换算：3000 OCPU 小时 + 18000 GB 小时／月，4C24G 全月跑刚好打满不超
  • 缺点：日区经常 Out of host capacity，需要抢

VM.Standard.E2.1.Micro（AMD 老款）

1/8 OCPU + 1 GB RAM ×2 台

x86 架构的老免费机型，配置很低（1GB 内存跑面板+Xray 会比较吃紧，多人使用容易 OOM）。好处是几乎不用抢，注册后基本能秒开。

  • x86 架构，兼容性问题最少，装什么都不用担心 ARM 兼容坑
  • 1GB 内存建议只跑 Xray-core，面板用命令行脚本管理而非网页面板，省内存
  • 可以两台 Micro 分别开在不同地区当"跳板+备用"，用来对冲 A1 被拉黑的风险

建议：主力用 A1.Flex 4C24G 跑 REALITY 节点，额度里剩余的 E2.1.Micro 白嫖一台当纯跳板/监控机，不占额外费用，两者互不冲突（Always Free 资源是叠加的，不是二选一）。

02
抢机策略：解决 Out of Host Capacity

日区（尤其 Tokyo）A1.Flex 免费额度长期紧张，创建实例时大概率第一次就会报错。这是容量问题，不是账号或权限问题，不用怀疑账号状态，耐心 + 脚本挂机即可。

1

先在控制台手动试 2~3 次

Compute → Instances → Create Instance，Image 选 Ubuntu 22.04 (aarch64)，Shape 改成 VM.Standard.A1.Flex，OCPU 给满 4、内存给满 24。如果不同 Availability Domain 可选，每个都试一遍——同一区域不同 AD 的容量池是独立的。

2

手动不行就上抢机脚本

社区有现成的开源方案（如 oci-arm-host-capacity），原理是用 OCI CLI/API 按固定间隔自动重试 LaunchInstance，一旦某个瞬间容量池腾出空位就立刻抢下来，比人肉手点效率高得多。

需要提前生成 OCI API Key（Profile → User Settings → API Keys），把脚本跑在你自己的 Mac 上或者一台常开的小机器上，通常几小时到一两天内能抢到。

3

实在抢不到的备选：换 Home Region 或先用 E2 过渡

Home Region 创建后不可更改，如果长期抢不到，短期可以先用 E2.1.Micro 把 REALITY 节点跑起来过渡，A1 抢到后再平滑迁移配置（VLESS UUID / REALITY 密钥对可以直接复用，只是换了台机器）。

03
面板选型：3x-ui 及其他选项

GUIDE.md 里提到的"协议是标准，软件是实现"同样适用于面板层——面板只是把网页点击翻译成 Xray-core/sing-box 配置文件，不参与实际转发。按维度对比：

推荐度 面板 驱动内核 成熟度 资源占用 备注
★★★★★ 3x-ui（MHSanaei） Xray-core 社区最大，更新最活跃，中文资料最多 中等（Web UI + 数据库） REALITY/VLESS/Vision 全支持，多用户流量统计、订阅链接生成、证书自动续期都现成。本方案首选。
★★★☆☆ s-ui（alireza0） sing-box 较新，同作者系团队维护，功能迭代快但资料少 中等 面板架构更现代，配置抽象层次更高；如果你后续想要 Hysteria2/TUIC 等 sing-box 独有协议，s-ui 是更自然的选择。
★★★☆☆ x-ui（alireza0 / 老牌 fork） Xray-core 最早的原始面板，多个 fork 并存（版本混乱） 最轻（低内存机型友好） 功能更简，适合 E2.1.Micro 这种 1GB 内存机型；生态里 fork 太多，选错仓库容易装到不维护的版本。
★★☆☆☆ 纯命令行（无面板，手写 Xray JSON） Xray-core / sing-box 最稳定（没有面板层 bug），但纯手工 最省资源，无 Web 服务额外开销 最安全的选择——因为压根没有一个公网 Web 端口可以被扫描器识别成"这是一台代理机"。适合只服务自己 1~2 台设备、懒得管理多用户的场景。

结论：A1.Flex 上装 3x-ui——资源够用、生态成熟、遇到问题好搜索。但切记 GUIDE.md 风险地图里最重要的一条：面板的 Web 端口本身绝不能对公网开放，必须走 SSH 隧道访问（下面第 4 部分会给出具体命令）。

1

创建实例时的关键选项

Image: Canonical Ubuntu 22.04 (aarch64)（LTS，Xray/3x-ui 官方脚本对它测试最充分）。Boot Volume 用默认 50GB 即可（Always Free 额度含 200GB 块存储，够分给多台）。

网络：新建或复用 VCN，务必在创建时把 公网 IP 类型选 "Reserved public IP"（预留公网 IP）——这样重启实例 IP 不会变，避免以后重新分发配置。

2

安全列表 / 防火墙：只开 443 和临时 SSH

Oracle 的 VCN 有两层防火墙：控制台的 Security List / NSG，和实例内部的 iptables/netfilter（Oracle 的 Ubuntu 镜像默认内置了额外的 iptables 规则，容易踩坑忘记这层）。两层都要放行 443（REALITY 用）和 22（SSH 管理）。

# 实例内部，Ubuntu 镜像自带的 iptables 规则要手动加放行
sudo iptables -I INPUT -p tcp --dport 443 -j ACCEPT
sudo netfilter-persistent save   # 或 iptables-save 持久化

# 面板监听端口（例如 2053）不对公网开——只在 Security List 里不开这个端口

控制台侧：VCN → Security Lists → Default Security List → Add Ingress Rule，Source CIDR 0.0.0.0/0，Port 443，Protocol TCP。SSH 的 22 端口默认已经开着。

3

一键安装 3x-ui

sudo bash -c "$(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)"

装完后脚本会打印面板的用户名/密码/端口，务必立刻用 x-ui 命令改成随机端口 + 强密码（脚本自带的交互菜单里有这个选项），别用默认值。

4

面板走 SSH 隧道访问，不开公网端口

在你的 Mac 上，把面板端口通过 SSH 本地转发到本机，浏览器只访问 localhost，公网上这个端口对外呈现"关闭"状态：

# 假设面板端口是 2053，服务器 IP 是 x.x.x.x
ssh -L 2053:localhost:2053 ubuntu@x.x.x.x

# 然后在 Mac 浏览器打开
http://localhost:2053

这一步对应 GUIDE.md 风险地图里的第 3 条——面板端口是最容易暴露"这是代理机"身份的信号，SSH 隧道让它在公网扫描器眼里始终是"未开放"。

5

在面板里新建 VLESS + REALITY 入站

面板内 Inbounds → Add Inbound：协议选 VLESS，端口 443，安全选 REALITY，点 "Get New Cert"/生成密钥对（面板会自动生成 private_key/public_key/short_id）。伪装域名（dest/handshake server）先用 www.apple.com:443 起步——按 GUIDE.md 提到的经验，微软家的域名实测握手通但传数据有问题，苹果这类"纯静态、无复杂 CDN 逻辑"的域名兼容性更好。

Flow 选 xtls-rprx-vision，Client Fingerprint 选 chrome（对应 uTLS 伪装）。新建一个 Client，拿到它的 UUID。

05
Clash Verge 客户端接入

3x-ui 面板可以直接导出这个入站对应的分享链接/QR，或者手动在 Clash Verge 的配置里加一个 proxy 节点，字段对应关系如下：

proxies:
  - name: "oracle-jp-reality"
    type: vless
    server: <你的服务器公网IP或域名>
    port: 443
    uuid: <面板里生成的 Client UUID>
    network: tcp
    tls: true
    flow: xtls-rprx-vision
    servername: www.apple.com        # 对应 REALITY 的 SNI 伪装域名
    reality-opts:
      public-key: <面板生成的 public_key / pbk>
      short-id: <面板生成的 short_id / sid>
    client-fingerprint: chrome
    udp: true

加进 Clash Verge 的订阅/自定义配置文件里的 proxies 列表，然后在你现有的分流规则组里把这个节点选进代理组即可。验证方式：切到这个节点后访问 whatismyip.com，出口 IP 应显示为东京。

如果你想要"举着牌子写清楚自己是谁"之外更省心的分发方式，也可以用面板的订阅链接功能——但按风险地图第 3 条建议，不要把订阅链接放在公网長期暴露，私下把面板导出的 JSON/YAML 片段直接发给自己（比如存进密码管理器）就够用，服务用户量小时没必要上订阅服务。
