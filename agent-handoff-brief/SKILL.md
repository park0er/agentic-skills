# Agent Handoff Brief

把当前会话打包成一份**让无上下文的 agent 冷启动理解**的交接文档。读者不是来接着执行任务的,而是来**理解现状**的。

## 六条核心原则(逐条遵守)

1. **冷启动定位,不是派活清单。** 文档让接手者"看懂在干什么、做到哪",而不是"照着这个继续干"。开头一句话点明:"这是背景交接,不是派活清单"。
2. **背景优先,可独立阅读。** 假设读者**没有任何前序对话**。项目是什么、为什么做、关键资料在哪,都要交代清楚,不能依赖"刚才说过"。
3. **如实标注真实状态:动过什么 / 没动什么。** 这是最重要的一条。明确写出哪些文件/系统被改过、哪些**保持原样**、哪些改动**已回滚**。若过程中有过越界改动并回滚,要写明,并提醒接手者**除非用户明确要求,不要改 X**。
4. **下一步是候选项,不是指令。** "可能的下一步"必须标注**待用户决定、勿擅自执行**。绝不把猜测的任务写成命令式待办。
5. **资料可定位。** 给绝对路径、链接、资源 id、工具用法。环境怪癖(如:非 git 仓库、需特定 CLI 认证、路径约定)单独点出,避免接手者踩坑。
6. **默认输出 Markdown。** 除非用户明确要 HTML/网页,只产出一份 `.md`。交接文档是工作交接,属"临时/一次性"性质,默认不双生成 HTML。

## 工作流

1. **盘点会话**:回顾本次会话做了什么——目标、读过的关键文件、产出物(文件/链接/资源 id)、被用户纠正过的点。
2. **判定真实状态**:逐一确认每个被触碰的对象现在是什么状态(改了/没改/已回滚)。**宁可多核实,不要凭记忆**——必要时用工具实际查看文件当前内容。
3. **套用模板**:按 [references/handoff-template.md](references/handoff-template.md) 的章节结构组织。按需裁剪,但"真实状态"和"下一步是候选项"两节不可省。
4. **写成 Markdown**:文件名用 `HANDOFF.md`(或 `<主题>-handoff.md`),放在与产出物同级的目录。引用本地文件用绝对路径。
5. **回报**:给用户一句话说明交接文档位置 + 它覆盖了什么,以及特别提醒接手者注意的点(尤其"不要改 X")。

## 反例(不要做的事)

1. ❌ 写成 TODO 清单,暗示接手者立刻开干 → 应是背景 + 候选下一步(标注待定)。
2. ❌ 默认假设读者知道前序对话 → 必须可独立阅读。
3. ❌ 漏写"哪些动过/没动",或把已回滚的改动说成已落地 → 必须如实、用工具核实。
4. ❌ 把猜测的下一步写成命令式指令 → 标注"待用户决定,勿擅自执行"。
5. ❌ 未经要求顺手出 HTML/双生成 → 默认只出 Markdown。
6. ❌ 只给文件名不给绝对路径/链接/资源 id → 接手者定位不到。
