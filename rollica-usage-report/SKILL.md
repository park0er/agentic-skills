# Rollica 使用报告

保留用户已确认的报告格式。使用打包的模板与渲染脚本，不从零重写报告，不把历史样例当成当前数据。

## 流程

1. **确定时间**：默认北京时间最近30个完整自然日，结束日为昨天；明确写出起止日期和不含今天。用户指定其他窗口时遵从。用 `python3 scripts/render_report.py --window` 得到默认窗口。
2. **查询前必读** [references/data-contract.md](references/data-contract.md)。使用当前可用的浏览器/Computer Use 工具及其文档；进入用户授权的小米云 SQL 页面。仅运行 SELECT / WITH...SELECT。复用有效登录；验证码、登录失效、无权限或浏览器不可用时停止查询并报告，不另建凭证或绕过限制。
3. **取全量数据**：核对当前表结构，按时间范围过滤 Work/Issue 事件，按规范化邮箱合并身份，再按邮箱和北京时间日期聚合；包括结束时已注册、当前仍存在的零消息账号。不能只取 Top25。不要查询消息正文。沿用已确认口径，不自行变更去重/归属规则。
4. **导出**：优先用查询 UI 的 CSV 导出，得到一列 `report`、一行 JSON 的完整结果；或使用浏览器支持的读取能力取得完整 JSON。校验结果未截断。不要把执行记录中的旧结果误当本次结果。
5. **生成**：运行 `python3 scripts/render_report.py --input /absolute/query.csv --output /absolute/rollica-usage-END.html`。接受 JSON 或单个 report 字段 CSV。使用全新日期目录，避免覆盖历史结果。脚本不联网、不查数据库，只验证并渲染文件；SQL 固化仍属后续待批准工作。
6. **验证**：数据须包含全量用户、每个用户逐日 Work/Issue；按用户和天加总与查询总数一致；未归属事件必须为0，否则停止并说明。用浏览器（若允许）检查头图、热力图、搜索、指标/色阶切换、排名、详情与导出。受限时做数据/脚本检查，明确没有实屏验收，不能绕过安全限制。
7. **交付**：给出 HTML 绝对路径链接、时间范围和2–3个关键数字。使用文件预览工具显示结果。成功任务必须通知有新报告；失败说明阻塞原因，不写“完成”。不要自动发布网站或同步用户明细到 Issue/飞书。

## 不变的报告合同

- 蓝色头图、指标卡、消息量与 DAU 分开绘图、全量逐日热力图、排行榜、口径说明。
- 热力图覆盖所有用户和每一天。默认按总量降序；包含零消息用户，注册前显示“—”而非0。
- 总量 / Work / Issue 切换；个人峰值相对色阶（原版）和统一绝对分档（0、1–5、6–15、16–30、31–60、61+）。
- 搜索姓名/邮箱；活跃、零消息、最近7天、期间新注册、渠道类型筛选；Top25/50/全部排行；点击用户/日期格显示逐日拆分；导出当前筛选的 CSV。
- 排名是本次窗口的总量排名。任何“最近7天”只是窗口内末7天（不足7天取窗口），不是登录活跃或流失判定。
- 不含升级前后、触达优先级或升级因果归因。不默认下发 gold 图标或改变配置。

## 定时运行

读当前 Scheduled 提示中的截止日期、时间、模型和输出位置；不要在技能里创建或修改调度。每次重新查数，不复用真实历史报表数据。重复同一天执行时可复用**已验证的同日成功结果**，但必须明示快照时间；不能把更早结果冒充新结果。

调度与项目跟踪见 [references/operations.md](references/operations.md)。需要管理 Rollica Issue 时使用当前已登录的 Rollica CLI；若本机已有 `rollica-management`，可用其包装器。写前复读 Issue 检查 assignee，避免唤醒未经授权的 Agent/Squad。只同步不含个人明细的运行状态，上传包含邮箱/使用量的报告需用户另外授权。

## 技能维护

仅在 Skill Factory 真源修改。模板内不保存真实用户资料、历史导出、token 或机器路径。先跑 `python3 scripts/test_render_report.py`，更新 CHANGELOG，执行 Factory dry-run/release 并核对安装目录一致；随后按 `FACTORY.md` 同步 Rollica 仓库目标、验证并提交。无需依赖其他 HTML 技能重新设计模板。
