# 三方DSP消耗波动诊断方法论

## 前置知识

### 核心概念

| 概念 | 含义 |
|------|------|
| 大盘总收入 | 全平台总消耗，含亿米内部投放 + DSP 外部投放 |
| 外部 DSP | 共 23 个，二级 DSP 名称如下：`tengxunrtb`、`bytedance`、`baidurtb`、`yyb`、`kuaishoudsp`、`chaojihuichuan`、`YOYO`、`iqiyi`、`xingchen`、`wangmairtb`、`vlion`、`wisemedia`、`jiatou`、`Feisuo`、`AdMate`、`fancy`、`Duomeng`、`kedaxunfei`、`kuaiyou`、`adprof`、`zhimeng`、`youjing`、`zhimeng1`。也可通过一级dsp = `DSP`，且二级dsp排除 `bytedanceUG`、`jingdongapi`、`tanxseat`、`pinduoduo`、`shoutao`、`bytedance_sdk` 的方式筛选|
| 亿米内部 DSP | 小米自有广告投放体系，诊断时可作为对照组 |
| 息壤效果看板（XirangAdEffect） | 曝光后链路数据，提供消耗、曝光、点击、eCPM 等指标 |
| ADX 链路多维分析看板（query_xirang_adx_diagnosis） | 外部 DSP 竞价链路漏斗数据，提供各环节的请求量、填充、竞胜等指标。**这是诊断外部 DSP 的核心看板** |

### 核心根因

任何一个收入波动，根因只有四类：

1. **库存变化**：媒体流量变化，从请求数可以看出来
2. **填充变化**：DSP 返回多少广告填充请求，可以通过填充率判断
3. **价格变化**：DSP 出价，可以通过 eCPM 和竞胜率来判断
4. **策略变化**：内部策略调整，如流量调配、出价系数或曝光策略等，影响漏斗通过率，参竞率和曝光率是参考指标之一

诊断的全过程就是不断追问"是量还是价"，然后逐层下钻找到具体对象。

### ADX 竞价链路漏斗

外部 DSP 从收到请求到最终产生收入，经过以下六个环节。每个环节的转化率下降都可能造成消耗下跌：

```
总请求
  │
  ├─ 填充率 = 填充数 / 总请求数
  │     ↓ 低说明 DSP 无广告返回
  │
  ├─ 参竞率 =（竞胜数 + 竞败数）/ 填充数
  │     ↓ 低说明 DSP 有广告但不参与竞价，可能是底价/定向过滤
  │
  ├─ 竞胜率 = 竞胜数 /（竞胜数 + 竞败数）
  │     ↓ 低说明 DSP 竞价能力弱，出价输给其他 DSP
  │
  ├─ 曝光率 = 曝光数 / 竞胜填充数
  │     ↓ 低说明竞胜的广告最终没被展示
  │
  └─ eCPM = 外部 DSP 消耗 / 曝光数 × 1000
        ↓ 低说明广告主出价或竞价意愿下降
```

**理论消耗公式（把上面六个环节串起来）**：

```
理论消耗 = 总请求 × 填充率 × 参竞率 × 竞胜率 × 曝光率 × eCPM / 1000
```

这个公式的用途：当收入下跌时，逐项排查每个环节的同环比变化，哪个环节跌得最狠，就是根因所在。

### 场景适配说明

本文档以「**掉量**」为主场景描述诊断流程，但四步法同样适用于「**消耗增长**」场景。两类场景的诊断骨架完全一致，差异仅在于判断方向和解读视角不同：

| 维度 | 掉量场景 | 涨量场景 |
|------|---------|---------|
| 定性判断 | 外部 DSP 是否比内部 DSP 跌得更狠 | 外部 DSP 是否比内部 DSP 涨得更多 |
| 定范围排序 | 按消耗变化绝对值升序（跌幅最大排第一） | 按消耗变化绝对值降序（涨幅最大排第一） |
| 漏斗解读 | 各环节转化率下跌 = 问题环节 | 各环节转化率上升 = 正向驱动环节 |
| 归因方向 | 追问"为什么跌" → 找到根因推动修复 | 追问"为什么涨" → 定位增长抓手，评估是否可复制 |

其余诊断步骤、数据拉取方式、下钻路径完全一致，不再单独展开。下文中出现「跌/下跌/掉量」等措辞的地方，涨量场景请反向解读。

## 诊断四步法

> **适用条件**：仅当用户话术涉及外部 DSP 消耗波动时才走此流程。面向的是外部 DSP 场景，不是 EMI 内部 DSP 投放诊断。

### 第一步：定性 —— 先搞清楚是不是外部 DSP 的问题

**目标**：确认波动是"大家一起跌"还是"只有外部 DSP 在跌"，避免在不是外部 DSP 问题的地方浪费时间。

**触发条件**：所有外部 DSP 消耗波动相关话术，第一步必须执行。

**操作**：拉双口径对照数据。

| 口径 | 用途 |
|------|------|
| 大盘总收入 | 全平台总消耗，看整体水温。直接用息壤效果多维分析看板看总收入 |
| 亿米内部 DSP | 对照组。内部 DSP 和外部 DSP 在同一个流量环境下的消耗情况，区别只在投放主体不同 。⚠️亿米内部DSP消耗可以用大盘总收入-外部DSP消耗|
| 外部 DSP | 诊断对象。⚠️ 查询时必须用 `dsp_level2` 按 23 个外部 DSP 名单（或排除法）筛，**不能**不加筛选直接拿外部dsp rtb消耗 当外部DSP消耗 |

**判断规则**：

| 场景 | 判别条件 | 判读 |
|------|---------|------|
| 大盘共性 | 外部 DSP 同环比变化与内部 DSP 同环比变化的**相对偏差 ≤ 5%**（即 \|外部DSP变化率 - 内部DSP变化率\| / \|内部DSP变化率\| ≤ 5%） | 两者波动方向与幅度基本同步，属于大盘整体波动，非外部 DSP 特有的问题。排查方向：流量波动、市场预算周期、季节性、节假日效应 |
| 外部 DSP 特异性 | ① 外部 DSP 同环比跌幅 > 内部 DSP 同环比跌幅，且相对偏差 > 5%；或 ② 外部 DSP 同环比跌，内部 DSP 同环比涨 | 存在外部 DSP 自身问题，可能是自身竞争力变弱，或是内部 DSP 竞争力变强 |

> 为什么做这步判断？因为需要给运营同学一个直观的大盘数据判断，初步评估这个问题的排查方向以及严重性。

---

### 第二步：定范围 —— 多维度下钻，定位"谁在跌"

**目标**：把外部 DSP 整体跌幅拆到具体对象上，找到跌幅的集中度。哪一个 DSP、哪个广告位、哪个客户的跌幅最高。

**必须做三阶段下钻**：

**数据排序与呈现规则**（适用于以下所有维度分析）：

- 按消耗变化的**绝对值**为主序排列，同时呈现每条数据的**波动比例**（同环比变化率）
- **掉量场景**：按绝对值**升序**排列，跌幅最大的排最前面
- **涨量场景**：按绝对值**降序**排列，涨幅最大的排最前面

> 为什么按绝对值而非百分比排序？绝对值反映对象对大盘的真实影响大小。小 DSP 跌 50% 可能只有几千块，大 DSP 跌 5% 可能是几十万——优先关注绝对值大的对象。百分比作为辅助参考，帮助判断波动的剧烈程度。

#### 阶段一：外部 DSP
> ⚠️ **这是第一步，必须先执行。后续阶段二、三均依赖本阶段的输出。**
**外部 DSP 筛选规则**（两种方式，任选其一）：

| 方式 | 筛选条件 | 说明 |
|------|---------|------|
| 方式一（正向名单） | 二级 DSP 限定以下 23 个名称：`tengxunrtb`、`bytedance`、`baidurtb`、`yyb`、`kuaishoudsp`、`chaojihuichuan`、`YOYO`、`iqiyi`、`xingchen`、`wangmairtb`、`vlion`、`wisemedia`、`jiatou`、`Feisuo`、`AdMate`、`fancy`、`Duomeng`、`kedaxunfei`、`kuaiyou`、`adprof`、`zhimeng`、`youjing`、`zhimeng1` | 按二级 DSP 名称精确匹配，直接命中外部 DSP |
| 方式二（排除法） | 一级 dsp = `DSP` 且 二级dsp排除 `bytedanceUG`、`jingdongapi`、`tanxseat`、`pinduoduo`、`shoutao`、`bytedance_sdk` | 先圈定 DSP 类型流量，再剔除非标/特殊渠道 |

> 两种方式理论结果一致，可互为校验。实际取数时选其一即可。

按 DSP 拉**消耗**（核心指标）、曝光、eCPM 的同环比变化，按消耗变化的绝对值排序（详见上方排序规则）。

#### 阶段二：外部 DSP × 广告位
> ⚠️ **本阶段依赖阶段一的输出。** 从阶段一的结果中取 Top 3 掉量 DSP，逐一与广告位做交叉。不要跳过阶段一直接用广告位排行替代。
取 Top 3 下跌 DSP 与广告位做交叉。这一步用于找到归因锚点——具体是哪家 DSP 在哪个广告位上的消耗出现问题。

#### 阶段三：外部 DSP × 广告位 × 客户
> ⚠️ **本阶段依赖阶段二的输出。** 从阶段二的结果中取 Top 10 下跌的 DSP × 广告位组合，再与客户做交叉。不要在阶段一没跑完时直接跳到客户维度。
取 Top 10 下跌的 DSP × 广告位组合，再与客户做交叉，查看具体是哪个客户掉量严重。最终结果取 DSP × 广告位 × 客户 Top 20 的数据呈现给用户。

---

### 第三步：漏斗排查 —— 竞价链路逐环节定位

**目标**：ADX 漏斗共有六个环节，定位收入下跌具体发生在哪个环节。

**核心下钻组合**：从第二步阶段二的 Top 3 中，取广告位 × 外部 DSP 掉量组合。

> **与第二步的关系**：第二步是宏观归因——把跌幅按 DSP/广告位/客户拆到具体对象；第三步是漏斗归因——按竞价链路逐环节定位转化率变化。两者是递进关系：第二步告诉你"谁在跌"，第三步告诉你"在哪个环节跌的"。

#### 3.1 漏斗各环节及排查含义

| 环节 | 指标 | 下跌时的含义 |
|------|------|------------|
| 请求 | 总请求数 | 上游流量供给减少 |
| 填充 | 填充率 = 填充数 / 总请求数 | DSP 无广告返回，可能是 DSP 侧预算/策略变化 |
| 参竞 | 参竞率 =（竞胜数 + 竞败数）/ 填充数 | DSP 有广告但不参与竞价，可能是底价/定向过滤 |
| 竞胜 | 竞胜率 = 竞胜数 /（竞胜数 + 竞败数） | DSP 竞价能力弱，出价输给其他 DSP |
| 曝光 | 曝光率 = 曝光数 / 竞胜填充数 | 竞胜的广告最终没被展示 |
| eCPM | eCPM = 外部 DSP 消耗 / 曝光数 × 1000 | 广告主出价或竞价意愿下降 |

数据来源：曝光数和 eCPM 从息壤效果看板获取，其余环节从 ADX 链路分析看板获取。

#### 3.2 排查流程

1. 取当期和对比期，按广告位 × 外部 DSP 下钻 ADX 链路漏斗
2. 计算各环节指标同环比变化，定位同环比变化绝对值最大的环节
3. 对变化最大的环节，查看过滤原因（adx_reason）分布
4. **补查效果看板**：对第二步锁定的 DSP × 广告位锚点，用 `query_xirang_ad_effect`（filter 对应 `dsp_level2` + `tag_id`）拉取**曝光（view）和 eCPM** 的同环比变化。这两项是漏斗的后两个环节，不能漏
5. 拉取内外部 DSP 消耗趋势对比，交叉验证

### 第四步：归因汇总与分层建议

**目标**：把所有发现串成因果链，输出可执行建议。

#### 4.1 归因金额拆解

将整体跌幅拆到具体锚点，每一行标注金额、占跌幅百分比、根因类型（库存变化 / 填充变化 / 价格变化 / 策略变化）。

#### 4.2 归因链条

用文字或树形结构梳理因果，三层结构：大盘共性贡献 → 外部 DSP 特异性的各个锚点 → 各锚点的金额和驱动因素。

#### 4.3 各环节下跌对应的后续排查方向

| 下跌环节 | 后续方向 |
|----------|---------|
| 总请求 | 排查媒体侧流量变化，可以和 ADPM 沟通 |
| 填充率 | 联系 DSP 侧确认预算/策略是否变化 |
| 参竞率 | 查 adx_reason 过滤原因分布（底价过低？定向过滤？超时？） |
| 竞胜率 | 对比其他 DSP 竞胜率，判断是被谁抢量（其他 DSP 包含内部 DSP） |
| 曝光率 | 可能与媒体的展示策略变化有关，或者是跟请求的时机调整有关 |
| eCPM | 结合第二步的 DSP × 广告位 × 客户交叉结果，定位哪些广告主在压价 |

#### 4.4 外部 DSP 诊断报告模板

最终报告必须是结构化 Markdown，包含以下 7 个部分，顺序固定：

**1. 诊断报告头部**

| 字段 | 说明 |
|------|------|
| 发起时间 | 本次诊断执行开始时间（格式：`YYYY-MM-DD HH:mm:ss`） |
| 数据窗口 | 异常时间段（起止日期/小时） |
| 对比窗口 | 对比期（如有），否则写"无" |
| 诊断场景 | 外部 DSP（口径：大盘总收入 / 亿米内部 DSP / 外部 DSP） |

**2. 总结快照（Summary Dashboard）**

高密度摘要，放在详细证据之前，至少包含：
- 外部 DSP 整体同环比变化（消耗 + 曝光 + eCPM）
- Top 掉量/涨量 DSP（按绝对值排序，掉量升序/涨量降序）
- Top 掉量/涨量 DSP × 广告位组合
- ADX 漏斗状态一览表（每个环节标注：正常 / 异常 / 无数据）
- 一句话根因
- 一句话版 L1 / L2 / L3 建议

**3. 定性结论（第一步证据）**

- 大盘总收入、内部 DSP、外部 DSP 三口径消耗对比数据
- 大盘共性 vs 外部 DSP 特异性判断结论
- 相对偏差数值（\|外部DSP变化率 - 内部DSP变化率\| / \|内部DSP变化率\|）

**4. 定范围结论（第二步证据）**

- 阶段一：外部 DSP 消耗变化排行（含波动比例）
- 阶段二：Top 3 DSP × 广告位交叉数据
- 阶段三：DSP × 广告位 × 客户 Top 20
- 每个阶段必须写出 `current vs comparison (change%)`

**5. 漏斗排查结论（第三步证据）**

- 按 Top 3 锚点逐一展示 ADX 漏斗各环节数据
- 标注每个环节同环比变化
- 定位变化最大的环节，注明 adx_reason 分布（如有）
- 内外部 DSP 消耗趋势对比（可用表格替代图表）

**6. 归因汇总与分层建议**

- **归因金额拆解表**：锚点 + 金额 + 占波动百分比 + 根因类型（库存变化 / 填充变化 / 价格变化 / 策略变化）
- **归因链条**：三层因果（大盘共性贡献 → 外部 DSP 各锚点 → 锚点金额与驱动因素）
- **L1 / L2 / L3 分层建议**：

| 层级 | 责任方 | 可执行动作举例 |
|------|-------|--------------|
| L1（DSP 侧操作） | DSP AM / 广告主 | 补充预算、恢复投放策略、调整出价 |
| L2（内部运营接入） | 平台运营 | 加系数提价、加白名单、跟进特定过滤项 |
| L3（研发介入） | 研发 / 系统团队 | 模型偏差、调价逻辑异常、看板字段/链路问题 |

> 每层建议必须有前文证据支撑，证据不足的层级不要硬写。

**7. 本次执行日志**

首行汇总：
```
[总计] N 轮调用 | 总耗时 Xs | 成功 N / 空数据 N / 错误 N
```

逐轮记录（每轮一行）：
```
[#N] <工具名> | 耗时 Xs | <状态: 成功/空数据/错误>
     → 查询参数: （只列关键非默认参数，不要贴完整 JSON）
     → 返回摘要: 共 N 行, 关键值: xxx=N, change=±N%（空数据或报错时写原因）
```

## 常见坑

1. **不要用 view 当流量数据**：view 是竞价结果不是真实供给，流量供给只看请求数
2. **周同比必须同星期几**：周一对周一，周六对比周六
3. **ADX 漏斗优先用广告位 × 外部 DSP 下钻**：这是运营验证有效的排查组合，不要单独只按一个维度看
4. **一个媒体跌幅超过整体跌幅是集中度高的特征**：说明其他媒体在回补，不是算错了
5. **绝对值比百分比更重要**：小 DSP 跌 50% 可能只有几千块，大 DSP 跌 5% 可能几十万，优先按绝对金额排序
