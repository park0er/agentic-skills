# 飞书招聘：筛简历 + 约面试

一条端到端流水线：**取数 → 读全文 → 按标准分档 → 出报告 → 提交结论 → 约面**。
除「筛人标准」以外的每一步都是固化流程，标准本身是可替换插件。

## 0. 先确认筛人标准（唯一的插件点）

读 `references/screening-criteria.md`。

判学校层级时**一律查表，不要靠记忆**——记忆一定会错：

- 国内 985 / 211 → `references/domestic-985-211.md`
- 海外 / 港澳台 QS 排名 → `references/qs-top100.md`

三处（含特例白名单）都查不到的院校，按"不满足学校底线"处理并在报告里标注。

- **文件存在** → 按它执行，不要自己另发明口径。执行前用一句话向用户回述你读到的档位定义，避免标准漂移。
- **文件不存在或只剩模板占位** → **停下来先访谈**，不要凭直觉筛。问这五件事，然后把答案写成 `references/screening-criteria.md`（格式照 `references/screening-criteria.template.md`），再继续：

  1. 学校口径：哪些学校算达标？按本科还是最高学历判？
  2. 硬性门槛：届次 / 毕业时间、岗位、是否排除已终止的投递
  3. 加分维度：要重点高亮什么（例如 AI 经历、自驱程度、特定行业）
  4. 排序偏好：档位之外还要按什么排（例如性别、毕业年份）
  5. 输出偏好：只要名单，还是要 HTML 报告 / CSV

  写完后确认一遍再跑。标准是用户资产，不要在后续对话里悄悄改它——要改就明说并更新文件。

**分发给他人时**：删掉 `references/screening-criteria.md`，只保留 `.template.md`。skill 会自动走访谈分支。

## 1. 取数：必须走接口，不要抓 DOM

候选人列表是 **canvas 渲染**的，`document.body.innerText` 里只有筛选器和分页，一行数据都没有。任何"读表格"的尝试都会返回空。

用 Rollica Browser 在已登录的页面上下文里调接口（详见 `references/feishu-hire-api.md`）：

```bash
multica browser nodejs < scripts/fetch_evaluation_list.js
```

跑之前在 workdir 写 `./hire_task.json`：

```json
{"activityStatus": 1, "filters": "{}", "out": "candidates.json"}
```

`activityStatus`：`0` 全部 / `1` 待评估 / `2` 已评估 / `3` 无需评估。
回捞场景用 `3`（别人已处理、你没评过）；新批次用 `1`。

**取完必须核对总数**和页面上「N 个结果」一致，并报告去重后人数（同一 talent 可能有多条投递）。

## 2. 判届次：优先用毕业时间比官方窗口

`graduate_year` 脏（有人填 2026 有人填 2027、有人空），**不能单独采信**。

按这个优先级判：

1. **`education_list` 里最高学历的 `end_time`（毕业时间）是否落在标准文件给的届次窗口内** —— 首选，精确口径
2. `graduate_year` 只做交叉校验
3. 前两条都拿不准时，才退回 **`biz_create_time` 投递批次聚类**兜底（同一届校招的投递时间集中在同几天）

先打印按月分布看清池子结构，再报口径，并把口径讲给用户。

## 3. 读简历全文，不要关键词计数

关键词命中数会把"技能栏写了 AI"和"真做过 Agent 0→1"排在一起。必须逐份读。

```bash
multica browser nodejs < scripts/fetch_resumes.js   # 默认每批 14 份，反复跑到 todo 0
```

简历全文在 `https://mi.feishu.cn/hire/talent/<talent_id>` 的 `document.body.innerText` 里（附件 PDF 已被平台解析成文本）。脚本会轮询到文本长度稳定为止，并把结果 append 到 `resumes.jsonl`（可断点续跑）。

详情页同时能拿到**列表接口给不了的关键信息**，读的时候一并记下：
- 该候选人**其他投递**的历史评估记录（谁拒过、评语是什么）——多次被拒是强信号
- 笔试分数（能力倾向 / 心理风险 / AI 潜力模型报告）
- 面试记录与终止原因

## 4. 分档时必须同时输出"短板"

只给优点等于没筛。每个进榜的人都要写清 **为什么进** 和 **短板是什么**（学校差一档 / 无对口经验 / AI 只是工具层 / 年龄偏大 / 曾被拒过）。用户要能只看卡片就下结论。

靠「AI 特别过硬」越档进主名单的人必须单独标 **`AI 越档`**，并写明命中哪一条 AI 核心判据、哪一项 🔥 自驱证据。写不出具体证据就不算越档。

## 5. 报告：完整披露，不要只讲你看好的

**这是最容易犯的错**：把 A 档讲透、B/C 档只塞进 HTML 不在对话里提，用户会发现"你跳过了人却没告诉我"。

对话回复里必须做到：
- 每个档位**至少列全名字**，高档位逐个给理由
- 明确写出"这批共 N 人，我点名了 M 个，剩下的是谁"
- 主动说明**你的排序权重**，并和标准文件核对是否一致；不一致要挑明

HTML 报告用 `scripts/build_report.py`，视觉规范见 `references/report-template.md`。要发给同事就用 `protofly` skill 挂内网。

## 6. 提交评估结论（写操作）

只在用户**逐个点名**后提交，不要根据自己的档位批量点。

```
POST /atsx/api/evaluation/evaluate/   {"conclusion": 1, "evaluation_id": "<evalId>"}
```

`conclusion`：`1` = 通过，`2` = 不通过。UI 上是两步（选通过 → 评价框可留空 → 点提交），接口一步等价。

- **评价框留空**，不要替用户写评语。
- 提交后必须用 `list_v2` 复查 `conclusion_info.name` 和所在页签，逐个报告结果。
- 被 `BROWSER_HUMAN_INTERRUPTED` 打断时**不要重放**：先用 `list_v2` 观察实际状态，只补没生效的。

## 7. 约面试

见 `references/interview-scheduling.md`。要点：

- 入口是 **我的任务 → 待安排面试**，不是候选人模块
- 用户给的名单和系统里的「待安排面试」**经常不一致**（已约完的会出列）。先逐个核对实际状态，已经约好的不要重复发
- 通知模板、面试联系人、视频工具都有既定值，照 reference 用，不要自己选
- 发之前查用户日历有没有冲突，**发现冲突照用户指定的时间执行，然后单独提醒**
- 误点产生的多余时间块要立刻取消并说明

## 8. 权限边界（先确认，别白跑）

「候选人」模块（`/hire/application/list`，全量投递、能直接约面）对只挂面试官角色的账号**所有阶段都是 0 条**。可用池就是「我的任务 / 简历评估」这几个页签。上手先确认这一点，省掉一轮无效探索。

## 只读纪律

取数、读简历、查日历全部只读。**写操作只有两类**：提交评估结论、发起面试邀约，且默认**都必须用户逐个点名**。不改筛选视图、不恢复已终止投递、不动别人的评估。每次收尾把列表页恢复原状并声明"动过什么 / 没动什么"。

**唯一例外——无人值守授权**：如果调用方（例如定时巡检的 autopilot）在其任务指令里**显式声明了无人值守授权**，并写明放开哪一项、收紧哪一项，则按该声明执行。典型形态是：放开「满足门槛即自动提交通过」，同时收紧为「禁止提交不通过、禁止发起面试邀约」。

没有这种显式声明时，一律按"必须用户逐个点名"办。**不要自己推断出授权**——"用户让我自动跑"不等于授权写操作。

## 常见坑

| 现象 | 原因 / 处理 |
|---|---|
| 表格读出来是空的 | canvas 渲染，走接口 |
| `gender` 全是 null | 该租户不采集性别，详情页和可选列里都没有。只能按姓名推测，必须标注"推测"和判不准的人数 |
| `total_count` 是 0 | 用 `data.count` |
| 一次 evaluate 好几个就超时 | 每次 `page.evaluate` 里别串太多请求，分批 |
| `提交` 按钮 matched 2 elements | 有隐藏同名按钮，用 `getBoundingClientRect().width > 0` 过滤后按坐标点 |
| 简历抓下来只有 12 个字符 | talent_id 用错了（别把 education id 当 talent id） |
| 同一人出现多次 | 按 `talent_id` 去重，但保留每条投递的 stage |
