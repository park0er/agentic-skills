# feishu-hire-screening CHANGELOG

## 2026-09-25 — add-official-27-baseline-and-985-211-list

- **筛人标准改为两层结构**（`references/screening-criteria.md`）：
  第一层「公司官方底线（27 届校招）」决定能不能要，第二层「本人档位」决定自动通过。
  两层是包含关系不是替代关系；**AI 越档通道也不能越过官方底线**。
- **新增 `references/domestic-985-211.md`**：固化 985（39 所）与 211 现存名单（112 所，
  含地矿油分家校区共 115 条）。来源维基百科相应条目（底稿为教育部 2009-01-05
  《"211工程"学校名单》），程序化生成并校验"985 全部包含于 211"。
  附公司特例白名单（中国科学院 / 西安邮电大学）与易错点（三组分家校区、
  西南大学非 985、双一流≠211 等）。
  **动机**：211 有 112 所，靠模型记忆判"是不是 211"一定会错。
- **官方底线五条判据**（来源《小米集团 2027 届全球校园招聘手册【面试官版】》）：
  1. 届次窗口 **2026-09-01～2027-08-31 毕业**的 2027 届海内外应届生
  2. **年龄 ≤ 26 岁**（官方写"不大于 2N"，N=13 为校招生初始职级）
  3. **本硕 GAP ≤ 1 年**；只有本科学历、不读研的不适用
  4. 学校底线 **985&211 + QS100 + 中科院 / 西安邮电大学**
  5. 心理测评风险度为**低 / 较低**
- **新增「数据缺失时怎么办」的单向否决原则**：届次与学校属"必须证明满足"，缺数据不通过；
  **年龄、本硕 GAP、心理测评属"只能用来否决"**——读到且不合格则禁止自动通过，
  读不到则不否决、照常自动通过并在报告里标注。（年龄与 GAP 的这一性质是按心理测评同类逻辑推定。）
- **明确记录两条故意不收录的官方内容**，防止回归：官方「AI 能力：有过 AI 的使用经验」
  （门槛过低会干扰第三节 AI 判据）、官方「提升硕博占比」（档位一律看本科）。
- 届次判定方法升级：优先用 `education_list` 最高学历 `end_time` 比官方窗口，
  `graduate_year` 仅交叉校验，`biz_create_time` 批次聚类降为兜底（`SKILL.md` 第 2 步同步）。
- 新增第五节「可入职时间」：**能提前 / 越早来实习的要 highlight 并按时间排序参考**；
  是 highlight 项，不是门槛也不是越档理由。（此前误将官方"实习优先"理解为实习履历加分。）
- B / C 档补充说明为"典型代表非穷举"，落在 985/211 名单内但未点名的按 C 档处理。
- **`SKILL.md` 只读纪律新增「无人值守授权」例外**：调用方显式声明并写明放开/收紧项时
  才可自动提交结论；禁止自行推断授权。这是为定时巡检 autopilot 留的唯一合法口子，
  避免 skill 与 autopilot 指令互相矛盾。

## 2026-09-25 — pin-qs-top100-and-ai-tier-override

- **新增 `references/qs-top100.md`：固化 QS 官方前 100 名单（QS 2027 版，2026-06-18 发布）。**
  数据从 QS 官方 Excel（`insights.qs.com/hubfs/...2027 QS World University Rankings 1.1`）
  程序化生成，未经人工转录，并与官方发布文章第 1–25 名逐条核对一致。含并列共 102 条记录，
  其中海外/港澳台 1–50 共 45 所、51–100 共 51 所、中国大陆 6 所（不走 QS 档）。
  附人工补充的中文名 / 缩写对照列用于匹配简历用词，以及易错点清单
  （Institute of Science Tokyo = 原东京工业大学、两所 NTU、UCL vs UCD 等）。
  **动机**：判"是不是 QS 前 50 / 前 100"靠模型记忆一定会错，必须查表。
- **筛人标准三处实质修订**（`references/screening-criteria.md`）：
  1. **消除岗位对口既是门槛又非门槛的自相矛盾**。旧版「权重顺序」说岗位对口不是准入门槛，
     「硬性门槛」一节又把岗位列成门槛。现在硬门槛只剩两条（届次、排除已处理），
     岗位对口明确只加分；且**"对口"的定义改为 AI 相关优先于广告相关**。
  2. **H+ 档上限从 QS 250 收到 QS 100**。海外本科 QS 100 开外一律不达标，
     这是硬天花板，不因 AI 强而破例。
  3. **新增「AI 特别过硬」越档规则**：H+ / B / C 档可凭此进主名单。判据必须同时满足
     `AI 深度 = AI 核心档` **且** `有 🔥 自驱证据（可指认的作品/名次/线上产物）`，
     只满足一条不算。越档进来的人必须单独标 `AI 越档`，不许混进 S/A/H 假装同档。
- 自驱 / 对 AI 热衷从"装饰性标签"提升为与学校档位同等重要的越档判据之一。
- 新增两条个人偏好记录：**抢人有时间竞争**（够格就尽快放行，宁可多放一个进下一轮）、
  **拒绝要慎重**（不可逆，拿不准就别动）。
- 独立学院 / 民办本科维持不自动放行，即使 AI 极强也要单独提出让本人定。
- `SKILL.md` 同步：第 0 步指向 `qs-top100.md` 并禁止靠记忆判排名；第 4 步要求标注 `AI 越档` 及其证据。

## 2026-09-24 — initial-release-screening-and-interview-pipeline

- 首次发布。端到端操作飞书招聘（mi.feishu.cn/hire）筛简历 + 约面试的固化流程。
- **插件化设计**：筛人标准是唯一可替换部分，放在 `references/screening-criteria.md`。
  主流程第 0 步先读它；文件缺失或只剩模板占位时**先访谈用户**（5 个固定问题），
  把答案写成该文件后再开跑。分发给他人时删掉这个文件即可，
  `references/screening-criteria.template.md` 留着做骨架 + 访谈脚本。
- 本次同时收录了赵锡盛的标准（商业化产品经理 / 校招）：
  权重 **学校 > AI > 岗位对口**，学校按**本科**判档（S 清北 / A 华五+人大 / H 海外 QS50 /
  H+ QS50-250 且 AI 硬 / B 顶级 985 默认不进主名单 / C 其他 985 与强 211 做备选），
  AI 四档 + 🔥 自驱标记，排序档位 → AI → 男性优先。
- `references/feishu-hire-api.md` 固化了本次逆向验证过的接口与字段语义：
  - 列表是 **canvas 渲染**，DOM / OCR 都抓不到，必须走 `POST /atsx/api/evaluation/list_v2/`
  - `activity_status` 四个页签的真实语义（3 = 别人处理过、你没评过 = 回捞池）
  - `data.total_count` 恒为 0，要用 `data.count`
  - 判届次用 `biz_create_time` 聚类，`graduate_year` 脏
  - **该租户不采集性别**：`gender` / `gender_info` 全量为 null，详情页与可选列都没有
  - 简历全文在详情页 `innerText`（PDF 已解析），详情页还独有历史评估记录、笔试分数、终止原因
  - 提交结论 `POST /atsx/api/evaluation/evaluate/` `{conclusion:1|2, evaluation_id}`
  - 「候选人」模块对纯面试官账号全阶段返回 0 条（权限），别在那浪费时间
- `references/interview-scheduling.md` 固化约面流程：先和「待安排面试」对账
  （用户名单与系统列表经常不一致）、查日历冲突、已验证的通知模板/联系人/视频工具配置、
  误点时间块要当场取消、收尾报告格式。
- `scripts/fetch_evaluation_list.js` 全量取数并直接打印投递批次/阶段/gender 分布。
- `scripts/fetch_resumes.js` 批量抓简历全文，append 到 jsonl 可断点续跑。
- `scripts/build_report.py` 从 `verdicts.py` 生成单文件 HTML（Swiss 视觉系统），
  自带三类校验告警：名单外的人、没打标的人、**缺「短板」的人**。
- 流程里写进两条防复发规则：
  1. **必须读简历全文**，不许用关键词计数打 AI 档
  2. **对话回复里每个档位都要列全名字**，不能只讲高档位把其余人埋在 HTML 里
     （这次实际踩过：B 档 11 人在聊天里一个都没提，用户追问才发现）
- 已知 gotcha：`multica browser nodejs` 的 cwd 恒为任务 workdir、环境变量不传递，
  所以 `hire_task.json` 必须写在任务 workdir 根目录；脚本会打印实际 cwd 并给出可读报错。
- 验证方式：两个 browser 脚本对线上「待评估」页签真跑通（31 条、简历全文抓取正常）；
  `build_report.py` 用 34 人真实数据生成报告，通过 tariq-html validator，
  浏览器里核对 34 张卡片 / 34 条短板 / 筛选与排序交互均正常。
