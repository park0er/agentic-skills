# 约面试流程

典型触发：用户把"已经跟候选人约好的时间"列表丢过来，要你在系统里发出正式邀约。

## 0. 先对账，别直接开干

用户给的名单和系统里的「待安排面试」**经常不一致**。真实发生过的情况：
用户说"正好这 5 个人"，但系统里的 5 个人里有 2 个是用户没提的（已约完的那两位早就出列了）。

所以第一步固定是：

1. 打开 **我的任务 → 待安排面试**（不是「候选人」模块）
2. 列出系统里实际的待安排名单
3. 对用户给的每个名字**逐个查当前状态**：
   - 已经有面试记录（时间、轮次、状态）→ **不要重复发**，报告已有安排
   - 在待安排里 → 本次要处理
   - 都不在 → 说明原因（可能已终止、可能不在你的任务里）
4. 把差异讲清楚再动手：**多出来的人一个字都不要碰**

## 1. 查日历冲突

在发之前把用户日历上对应时段拉一遍。

- 发现冲突：**照用户指定的时间执行**（他说了就是他说了），然后**单独列一条提醒**说明撞了什么。
  实例："9/28 19:00 撞了「商业平台部AT会 19:00–20:00」"
- 用户日历上可能已有同学帮忙占的**普通日程占位**（如"段然面试 10f-01 15:00–16:00"）。那不是系统面试，系统正式面试块会叠在同一时段上——要说明，别当成已经约好了。

## 2. 发起面试（每人一次）

在「待安排面试」里对该候选人发起安排。已验证的配置（**沿用这些，不要自己选**）：

| 项 | 值 |
|---|---|
| 轮次 | 1 面 |
| 形式 | 视频面试 |
| 视频工具 | 飞书（系统会记住上次选择，可能默认成「飞书（含代码考核）」） |
| 通知模板 | **2027届常规校招面试通知-视频面试邀约** |
| 通知渠道 | 邮件 + 短信 **都开** |
| 面试联系人 | 赵锡盛 / zhaoxisheng@xiaomi.com |
| 时长 | 系统默认 45 分钟 |

要点：

- **通知一定要带**。用户明确要求过"一定要带那个通知"。发之前确认模板名对得上。
- 「飞书（含代码考核）」对商业化产品经理岗用不上（只是多一个功能入口，不影响候选人收到的链接和邮件内容）。沿用即可，但**要在结果里说明**，让用户决定换不换。
- 起始时间按用户给的整点。已有的面试可能是 `:15` 起（历史按 45 分钟档排的），**新老不对齐要主动提**，问要不要统一。

## 3. 误操作立刻收拾

日历选时段时误点很容易多出一个空时间块。**当场取消，并在结果里说明"误点已取消"**，不要留着让用户自己发现。

## 4. 收尾报告格式

```
已发起（1 面 · 视频面试 · 飞书 · 通知模板「<模板名>」· 邮件 + 短信 · 面试联系人 <人/邮箱>）：

| 候选人 | 时间 | 状态 |
|---|---|---|
| ... | 9/28（周一）19:00–19:45 | 新建，邀约已发 |

本来就有、我没碰：
- <姓名> <时间>，状态「候选人已接受」

需要你确认的：
1. <时间冲突>
2. <整点 vs :15 不对齐>
3. <视频工具选项>

系统里还挂着但你没提、我没动的：<姓名 / 学校>
```

## 只读 / 写边界

- 查待安排列表、查已有面试、查日历 → 只读
- 发起面试邀约 → 写操作，**只对用户逐个点名的人做**
- 不取消别人已安排的面试、不改通知模板配置、不动用户没提到的候选人
