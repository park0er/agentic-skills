# 来源路由

按来源选择最可靠的正文获取方式。先拿到足够正文，再进入总结；不要为了“全文”绕过登录、付费、验证码或权限限制。

## 飞书文档 / 知识库 / 表格 / 云盘

- 看到 `*.feishu.cn`、`*.larksuite.com` 或用户明确说飞书时，必须调用现有 `feishu` skill。
- 读取统一用：

```bash
feishu fetch <url>
```

- 大文档先用 outline/keyword/section 等局部读取能力定位，再读取相关章节。
- 不使用旧命令：`mcp_feishu_fetch-doc`、`mcp_feishu_fetch-file`、`mcp_feishu_create-doc`、`mcporter`。
- 如果用户要求导出或同步到飞书，先读当前 `feishu` skill 的写入规范，再用 `feishu docx create/update`。

## X / Twitter

- 先判断输入是普通推文、长推文、短链还是 X Article。
- 推文只含 `t.co` 时，解析最终链接；若指向 `x.com/i/article/...`，优先读取 Article 正文。
- 优先使用公开可访问数据源、页面可见内容或官方嵌入数据。
- 不读取本地密码文件，不代替用户登录，不绕过登录墙或反爬虫。
- 如果只能获取预览或摘要，明确说明“只拿到可见部分”。

## 公众号 / 微信文章

- 优先读取公开页面可见正文。
- 遇到登录、关注、地区、验证、付费或客户端限制时，不绕过限制，只总结可见内容。
- 公众号文章常带强运营语气，总结时重点检查利益冲突、转化目的、样本偏差和时效性。

## 普通网页 URL

- 优先使用浏览器或网页读取工具获取正文。
- 正文抽取失败时，尝试页面标题、meta 描述、可见正文和结构化数据。
- 新闻、政策、价格、模型、产品规格等时效性强内容，必须确认发布时间和当前性。
- 如果页面是 PDF、文档、表格或代码仓库，切换到对应文件/仓库读取方式。

## 本地文件

- 直接读取用户给定路径。
- 大文件先看目录、标题、摘要、frontmatter 或用户指定章节，再按需读取细节。
- 不要改写源文件，除非用户明确要求保存总结或同步。

## 直接文本

- 直接总结。
- 如果文本像转写稿或零散笔记，先按主题聚类，再做四段式分析。
